## Judgment for the current problem

Recommend testing the state/action seam before adding another generic instruction,
fixed hat sequence or separate mediator architecture. Current core already requires
useful judgment, preserved authority and continuation. The recent source checks
include a PARTIAL handoff baseline and passing method/table baselines. Those results
do not explain the native recurrence by themselves.

| Finding transferred | Why it matters here | Transfer limit |
|---|---|---|
| Intervention timing can be wrong even with useful ideas | Brainstorm must develop or converge after creator feedback | PTFA is small group work, not direct solo-project efficacy |
| Preference and evidence quality can diverge | Agreement/critique should be justified, not optimized for tone alone | Older-model studies do not measure current incidence |
| Changing intent differs from static sufficient input | Fresh successful snapshots can miss context drift | Published simulators are not native Fab chats |
| Correct state and correct action are distinct | Diagnose whether the task is lost or the next action is withheld | A reminder is an intervention, not proof of recovery |
| Judges have material limitations | Preserve human complaints and observable outcomes | A second model is not automatic independent proof |

## Smallest useful next validation

Main should prepare one bounded sequential fixture from a sanitized dead-end
episode after the creator authorizes that next test. The proposed event sequence
is initial work, creator scope correction, completed stage and remaining authorized
goal. Assess at each consequential boundary, not only the final sentence.

Compare the relevant unchanged package with the candidate under the same runtime.
Use a fresh snapshot only as a diagnostic control, and a correct-state reminder
only as a separately recorded intervention if the sequence actually fails. Keep
genuine completion as a non-trigger control and one related unseen situation.
Set actual budget after a pilot, rather than choosing many long runs upfront.

Evaluation questions:

- Is the accepted goal/scope still correct after feedback?
- Does the reply contribute something needed at this stage?
- Does it execute already authorized work or expose the real blocking choice?
- Does it avoid reopening rejected scope and inventing work after completion?
- What work/attention did the creator have to supply to restore progress?

This is a proposed design. No new model turn, fixture superiority or causal repair
is claimed from the research. Current source release readiness and conversational
efficacy remain separate. Existing 66 regressions address structural integrity.
