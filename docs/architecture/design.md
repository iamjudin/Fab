# Fab architecture: current owners and read boundaries

Fab supplies ten independently usable skills, not a required pipeline or ten
agents. The runtime package is `plugins/fab`; its methods and instructions are
self-contained. Maintainer docs, Brain, archived plugins and test products are
not normal runtime dependencies. No orchestrator/MCP/queue/hidden swarm.

## Current distribution and source

The [backlog's current distribution](../backlog.md#current-distribution) owns the
actual published/installed version, receipt, rollback and remaining work. Keep
this architecture index about owners and boundaries, not a second version log.
A packaged/installed identity does not establish all-skill or native behavior.

## Capability ownership

| Capability | Owns | Boundary |
| --- | --- | --- |
| Cowork | Intent, accepted agreements, continuity and routing | Optional orientation; direct requests can skip it |
| Research | Independent findings, evidence synthesis/intake and qualified application | Research is not creator acceptance or empirical validation |
| Analysis | Grounded assessment of an existing object | Read-only review does not authorize redesign |
| Brainstorm | Alternatives, critique and consequential choices | No automatic implementation or fixed persona ceremony |
| Testing | Bounded discriminating evidence | Actual cost/stops and original failures retained |
| Product | Meaning, rules, ownership and requested behavior | No forced whole-model graph for a bounded edit |
| Wireframe | Visible organization, access, scenarios and composition | Tables default; Canvas opt-in experimental |
| Prototype | Executable selected interaction candidate | Browser simulation is not native/production delivery |
| Plugin | Plugin/source/package/runtime engineering | Checks/installation distinct from public release |
| Delivery | Actual implementation, handoff and requested distribution | Local update, public channel and real use separately verified |

## Information ownership

| Concern | Canonical runtime owner | Read trigger / evidence boundary |
| --- | --- | --- |
| Authority, collaboration and preservation | `shared/core.md`, decision/project policies | Direct skills read core; other refs only as applicable |
| Relevant knowledge | One current view/reader through `shared/methods/index.md` | Topic entry selects current meanings and their conditions; original source only as needed |
| Corrections and reusable-rule scope | [learning](../../plugins/fab/shared/learning.md) | Consequential correction/recurrence/proposal; not every small edit |
| Common interface expression | [interface principles](../../plugins/fab/shared/interface-principles.md) | Visible wording/composition through six conditional entries |
| Public-site content/scenario | [landing](../../plugins/fab/shared/landing-pages.md), [web content](../../plugins/fab/shared/web-content.md) | Actual public offer/service/information task |
| Reusable system construction | [design-system work](../../plugins/fab/shared/design-system-work.md) | Actual shared definitions, concept extraction or Figma/code ownership; target supplements conditional |
| Browser adaptation | [web layout](../../plugins/fab/shared/web-layout.md) | Browser presentation, including web apps; viewport is not native identity |
| Native behavior | [mobile structure](../../plugins/fab/shared/methods/mobile-structure.md) and actual platform guidance | Actual app input/Back/lifecycle/native question; no browser-native equivalence |
| Website technology | [web implementation](../../plugins/fab/shared/web-implementation.md) | Actual site code/technical review; accepted stack takes precedence |
| Distribution and transient artifacts | Release policy and artifact lifecycle | Actual release/install/scratch work; no automatic external authority |

A source finding, current instruction, local decision and executed result have
different authority. Fifteen packets preserve816indexed sections, qualifications
and historical examples. Common operational policy is linked once; scenario /
platform refs hold their actual differences. Existing project records and the
owning backlog hold local decisions/findings, without another learning registry.

One editable source under `knowledge/` owns75current meanings across twelve
registered families. The deterministic compiler, `scripts/build_knowledge.py`,
validates exact source bindings and emits the package-contained view. The bundled
reader returns selected meanings with necessary conditions/contradictions and
compact association leads. Topic entries route there rather than maintaining
competing working summaries. Original packets remain qualified evidence.

Research intake searches existing meanings before adding, enriches or replaces
their owner and switches affected consumers. Project evidence/preferences stay
local. Exact per-unit revisions support explicit local review/retirement.
Neither source retention nor current status establishes independent scientific
truth. Technology claims retain conditions and relevant fresh-evidence triggers.
There is no automatic background refresh or propagation into other projects or
generated plugins. A generated plugin needs its own deliberate, self-contained
knowledge selection and versioned update scope.

## What checks establish

Repository checks verify maintained/changed public-document links and install
pins; local staged checks can flag leftovers only in explicitly owned task roots.
They do not evaluate the truth of prose or delete files. Package checks separately
verify reference/branding/packet/registry integrity and the current
application-owner boundary of bundled briefs. They do not prove semantic ownership
or agent use. Regression coverage includes negative source-versus-policy mutations.
One fresh configured GPT-6.1 Sol/medium source review observes Analysis discovering
and applying correction learning to five fictional cases. Two earlier supplied-
context interface probes qualify platform/stack separation. Native/installed
adoption, sustained use, organic landing quality and scalability remain open.

Two fresh source contexts preserve17cross-family/design distinctions. A separate
writable Test copy ingests raw material, enriches an existing meaning, switches
a stale entry and keeps local preference out of shared authority. These are
bounded supplied-snapshot checks under normal host context, not organic/native/
installed-model, all-skill or universal reliability evidence.

Canvas has a bounded actual file/check/correction pass plus retained earlier
recovery/overflow misses and timeout/unknown usage. Browser prototype, native
behavior and user value stay distinct. No averaging of partial results into PASS.
