# Fab architecture: implementation boundary
Design v0.2 accepted for bounded autonomous beta implementation on 2026-10-10.
Target owners: cowork, research, product, wireframe, prototype, analysis,
brainstorm, testing, plugin, delivery. Historical beta.1 had five skills:
cowork/research/analysis/brainstorm/testing plus shared core.
All ten skill contracts are now installed in beta.17. Meaning/behavior maturity
is bounded by concrete smoke evidence, not availability. Product/Wireframe use
compatible graph adapter; Prototype/Plugin/Delivery have independent modes.
Cowork maintains collaboration/intent/continuity; direct invocation bypasses it.
Research acquires/synthesizes evidence; analysis evaluates existing material;
brainstorm explores alternatives; testing produces experimental evidence.
Delivery future owner of public release; plugin owns packaging/runtime criteria.
Common Git culture is not a separate skill. No orchestrator/MCP/queue/hidden swarm.

New repo with independent history, package plugins/fab, portable package-root plugin.json.
Old repositories remain untouched source/recovery. Selected reusable knowledge
pairs copied with hashes/limits; project reports/test products excluded.
Mobile method now has brief/full and conditional app routes; native/device
behaviour and gamification remain separate evidence gaps. Landlord excluded.

Shared artifact lifecycle covers task-owned scratch, verified retention and
bounded cleanup. Plugin exports an equivalent self-contained rule to generated
packages; this is a runtime responsibility, not a new mandatory workflow stage.
Beta.10 installed parity/local regression checked; fresh generated-rule behavior
not yet observed (FAB-09).
Beta.11 makes maintainer research labels explicit: `Fab:` filename prefix and
top Fab marker/tag, preserving source titles, body and inclusion history.
Eight existing Brain originals migrated with verified hashes; runtime has no
dependency on those external originals. Fresh ingestion behavior not generalized.
Beta.12 extends research marking to optional project-name/tag annotation after
completed ingestion, additive labels and per-project usage/revision provenance.
Source change identifies affected projects; it does not authorize cross-project
updates or monitoring. This fresh behavior remains unobserved (FAB-10).
Beta.13 makes coauthor feedback operational in core/Cowork: assess a new proposal
with reasons and useful recommendations before edits, including clear requests.
No invented objections, fixed speech templates or approval gates for routine work.
Source/install checks do not establish behavioral improvement (FAB-11).
Beta.14 retains platform-neutral intent/UC/rules/slice and adds conditional
mobile structure/input/return evidence in Product/Wireframe/Prototype/Delivery.
iOS/Android/mobile web share methods, not identical navigation/input/lifecycle.
Desktop web can reuse meaning and adapt its surfaces/URL/browser conditions;
its completeness isn't claimed by the mobile research. No extra mandatory stage.
Beta.15 extends core/Cowork to post-work interpretation: a grounded judgment for
the project goal, practical consequences and a reasoned next action. Technical
assessment belongs to Fab; creator preferences/value/acceptance remain distinct.
Meaningful forks need concise options and a recommendation before dependent work;
no mandatory report template, extra skill gate or pause for authorized next work.
Beta.16 responds to two partial-route failures: the user-facing artifact handoff
must contain the useful synthesis even when the document already has it; an
existing UI mechanism is checked against domain behavior, not rejected because
its control name is absent from the Product model. Focused corrective evidence
is required separately from installed parity; initial failures stay in evidence.
Beta.17 clarifies the Product exit after beta.16's partial handoff improvement:
the reply needs its bounded design judgment/reason and next useful action,
without expanding to Wireframe or manufacturing a new process stage.
