## Assignment

Research how to evaluate the usefulness and reliability of a conversational AI
collaborator across an evolving, multi-turn knowledge-work task. Produce the report
in Russian. Study evaluation methods independently of a particular product.

The motivating evaluation problem is a discrepancy: short reconstructed situations
produce acceptable answers, while a person's ongoing work contains lost initiative,
unclear continuation or scope drift. Determine what evidence can distinguish an
instruction defect, weak context retention, unrealistic test input and a mistaken
quality criterion. Do not assume a particular cause or that more tests solve it.

### Required questions

1. Which units of evaluation capture collaboration: a response, decision, stage,
   session or longitudinal outcome? What does each unit miss?
2. How should realistic tasks preserve accepted decisions, evolving constraints,
   interruptions, earlier errors and genuine authority boundaries without leaking
   the expected answer into the test input?
3. Compare fresh snapshots, transcript replay, resumed sessions and observation
   of ordinary work. What claims can each support? What controls isolate context,
   package revision, user instruction and environment changes?
4. How can evaluators measure useful contribution, justified critique, progress,
   task completion and preserved human agency? Separate artifact validity, tool
   actions, self-reported completion and experienced value.
5. How should a passing baseline be interpreted when a real failure prompted the
   test? Examine fixture sensitivity, selective reporting, interventions and
   independent holdouts. Avoid unsupported comparative superiority.
6. What are the strengths and failure modes of human review, rule checks and
   model judges? Cover blinding, agreement, calibration, uncertainty and judge
   dependence. Distinguish synthetic user behavior from actual human acceptance.
7. How should a small team decide when evidence is sufficient to change or release
   an assistant? Compare bounded regressions, staged rollout, repeated use and
   targeted observation. Include failure retention and rollback criteria.
8. What economical evaluation design answers the next uncertainty? Account for
   token/context growth, latency, user attention and repeat runs. Avoid arbitrary
   universal sample sizes or treating cached tokens as account-limit percentages.

### Evidence and stopping boundary

- Prioritize original evaluation papers, primary benchmark protocols and empirical
  deployments. Clearly label specifications, proposals and unvalidated practices.
- Include both collaboration/interaction research and agent evaluation where
  relevant. Explain limits of transfer from coding or autonomous agents to a
  human-led evolving task. Do not generalize a single vendor's results.
- Retain original task, sample, comparator, outcome measure and judge protocol
  for important findings in a linked appendix. Include null/negative results.
- For recommendations distinguish supported findings, reasoned design choices
  and hypotheses. Name inaccessible sources and unsupported causal claims.
- Stop after covering each required question or declaring its evidence gap and
  producing a workable decision framework. Do not catalogue every benchmark or
  require exhaustive evaluation before any reversible improvement.

### Topic-specific presentation

Begin with what a small team can and cannot conclude from available evidence.
Use a compact comparison of evaluation methods: uncertainty answered, realistic
context retained, main blind spot and cost. Put detailed protocols outside cells.

Include one minimal worked example: a true multi-turn handoff failure, a passing
focused baseline, a corrective intervention and a separate check. Show how the
conclusion changes at each step without inventing experimental data. Label the
example as illustrative. Then give an ordered design procedure and a short list
of stop/escalation signals. Retain competing approaches and their tradeoffs.

### Output contract

Prepare clean Markdown for Obsidian in Russian. Use meaningful headings and
navigation for a substantial report. Begin with the answer or useful orientation,
evidence status and main limitation. Use compact tables for comparisons and
repeated short fields, lists for independent items, numbered steps for procedures
and short paragraphs for causal explanation. Put multi-field details on separate
lines and keep each detailed profile once.

Avoid long prose in table cells and repeated summary layers. Preserve counterevidence,
conditions, uncertainty and source traceability. Keep extensive evidence in a
linked appendix. Do not use semicolons in newly authored reader text. Preserve
code and exact quotations. Use descriptive Markdown title-links near claims,
without numeric citations or export markers. Group sources by section at the end
under a localized Sources heading. Prefer tables/lists to diagrams. Use editable
Mermaid only when it adds understanding and fits an ordinary note pane without
horizontal scrolling. Vertical orientation alone is insufficient.

Before delivery review the opening and a dense section for scanning, reasoning
and evidence fidelity. Each required question must have an answer or named gap.
Reconcile any numbers, assumptions and comparisons. Link empirical claims to
actual supporting evidence and state the report date. State unverified rendering
and unresolved source limitations. This assignment is not a completed investigation.
