# Knowledge organization and correction learning audit

2026-10-21. Scope: all twelve bundled method briefs and their registry/index,
all ten skill entry contracts, current shared policy owners and the relevant
research/runtime/experiment references. Link inventory covers the package; this
is not a new claim-by-claim scientific audit of the572preserved source sections,
nor a semantic reread of every historical example or every possible task path.

## Judgment

Keep the existing independent skills, brief/full pairs and single method registry.
They already separate source knowledge, current application and qualified limits.
Do not rebuild the library, flatten source variation into policy or create a
second rule/lesson registry. The actionable gaps are conditional discovery,
current-owner clarity and the transition from a correction to the right repair.

## Grounded findings and repairs

1. **Discovery is weaker than graph reachability.** All methods can be reached
   through package links, but that alone does not tell a direct skill when to read
   the index. Core now conditionally points to the matching brief when existing
   knowledge can change the active decision; deeper source reads remain selective.
2. **Correction-to-rule reasoning was fragmented.** Plugin required root cause,
   Testing had findings triage and core required learning, without one operational
   distinction across local preference, undiscovered rule, ignored rule, ambiguity,
   missing reusable condition and test/environment failure. One conditional
   `shared/learning.md` supplies that distinction and ownership/authority boundaries.
   Analysis, Testing, Plugin and research maintenance link it; no new queue/schema.
3. **Current application owners could disappear while sources remained valid.**
   The existing guard checked pairs, hashes/index and links, but would accept a
   brief with no executable current-policy owner. The existing brief application
   boundary now requires a local policy/skill/reference owner outside the source-
   method set. Negative mutations remove the boundary, use another brief, or use
   only the original packet; each must fail. This is structural protection, not
   proof that the linked owner is semantically correct or actually read.
4. **Interface owner links lagged the integrated source.** Typography/design-system
   briefs and the method index now point to the common current-policy owner and
   applicable browser/public-site differences. Preserved research is unchanged.
   Canvas is described as experimental, not a nonexistent parked implementation.
5. **Runtime-helper instructions assumed an ambiguous script root.** Historical
   landing/release work retained that actual lookup failure. Plugin runtime now
   links the bundled comparator relative to its reference, avoiding a repository-
   root assumption. Package reference checks can detect a missing helper.

6. **The architecture index mixed current ownership with successive historical
   current-state labels and old method counts.** The prior text is retained verbatim
   in a dated architecture snapshot. The active index now contains current owners,
   read triggers, installed/source separation and proof boundaries. History is
   linked rather than treated as another active instruction layer.

Original failures remain in their dated evidence. These repairs do not close
native dialogue reliability, scientific citations, source freshness, automatic
host reload, discovery of every method or broad product scalability.

## Sustainable learning without rule accumulation

Use the current owner and existing backlog. First establish the observation and
cause; then choose local repair, discovery repair, application/preflight repair,
clarification, bounded reusable change or evidence/setup work. Recurrence is a
signal, not a quota: a single causal contradiction can justify repair, while many
similar-looking outputs may have different causes. Retain a contrasting valid
case to challenge overgeneralization when it changes the conclusion.

The evidence determines the update's scope, not the number of files or incidents.
A project preference stays with that project. Shared principles need actual
cross-capability applicability; scenario/platform guidance specializes conditions.
Meaningful findings use existing backlog statuses/owner/next/closure boundaries.
Small completed corrections need no lesson document. Learning grants no plugin,
global, cross-project, provider or publication authority by itself.
