# Fab0.1.0-beta.27 — continue active dialogue after feedback

Scope feedback updates the current project goal. After acknowledging a correction,
Fab reconnects to remaining work and actual authority: perform the authorized next
action, develop the selected direction or ask a concrete blocking question.

- Rejecting an extra study preserves unaffected work.
- A pending creator choice should be named, with its effect explained.
- Describing a future action is not completing it.
- Completed small requests and thanks can end naturally, without compulsory
  questions, new tasks or a next-step paragraph.

The canonical shared boundary applies to direct Fab skills. Brainstorm's dialogue
reference uses the same stopping principle.

## Verification and limits

Four fresh GPT-6.1 Sol/Medium turns include a shipped-beta.26 baseline and three
candidate cases. Candidate gives a concrete scope question, delivers two already
authorized drafts and keeps a completed-thanks reply short. Fifty regressions pass.
The fresh baseline also passes the scope-question case. The actual native miss
is preserved: superiority and long-context repair are not established.

No automatic existing-chat refresh, installed-model execution, new external
research or native-render guarantee. Brainstorm's revised progressive reference
is structurally reviewed, not independently invoked in those model cases.
Bookworm and experimental Canvas remain separate. Prior tags are immutable.
