# Fab — brainstorm, build, ship

**Fab**, short for **Fabricator**, helps indie creators turn ideas into useful
products. Think through decisions, shape an interface, build a prototype or
prepare a release. Use one skill on its own or connect the steps your project needs.

## Use cases

- **Challenge an idea.** “Is this app worth building? Challenge my assumptions and recommend a first test.”
- **Explore possibilities.** “Suggest three approaches, explain the tradeoffs and recommend one.”
- **Review what exists.** “Audit this onboarding flow and identify the most useful improvement.”
- **Use research.** “Turn this study into decisions we can apply to our project.”
- **Shape and prototype.** “Define this feature's behavior, organize the screens and build a prototype of the critical interaction.”
- **Build a landing page.** “Use this offer and approved copy to build a responsive landing page, keeping the stack simple.”
- **Build and ship a plugin.** “Repair this skill, check its installed package and prepare a GitHub release.”
- **Continue a project.** “Recover our decisions, open questions and next useful action.”

## How Fab works

**Brainstorm:** Cowork, Research, Analysis, Brainstorm and Testing help you frame
questions, gather evidence, compare options and run focused checks.

**Build:** Product, Wireframe, Prototype and Plugin define behavior, organize
interfaces and create executable candidates or plugin packages.

**Ship:** Delivery checks feasibility, prepares handoff and organizes a release
for the agreed channel. Each skill also works independently.

## Install

Use a Codex client with plugin marketplace support:

```sh
codex plugin marketplace add iamjudin/Fab --ref v0.1.0-beta.33
codex plugin add fab@fab-local
```

Already installed? See [update and rollback](docs/install.md).

Brainstorm develops ideas through grounded critique, meaningful alternatives and
focused questions. Six Thinking Hats perspectives are optional, not a fixed answer
format. When a task grows into an independent workstream, Fab proposes a separate
chat and transfers context after your agreement, subject to host support.

## Beta status

**Current version: 0.1.0-beta.33.** Mobile apps are the current focus, not a
product-size ceiling. Public websites and landing pages also have a conditional
route; each skill remains usable independently.

This maintenance release adds repository checks for public links, installation
pins and task-owned leftovers. These maintainer checks do not change installed
skill behavior. Recent versions also connect knowledge to the work that uses it:

- **Coherent interfaces.** Shared wording, grouping and typography principles
  have one owner, with separate public-site, browser and implementation guidance.
  Existing or explicitly chosen stacks remain in place.
- **Corrections at the right scope.** Fab distinguishes local choices, missed
  instructions, failed application and actual rule gaps before proposing a reusable
  change. Significant findings use the project's existing backlog.
- **Relevant knowledge on demand.** Skills consult applicable method briefs;
  source evidence, current rules and project decisions stay distinct. Package
  checks protect the links to current rule owners and original research packets.

Research also includes qualified methods for layout and typography, onboarding,
motivation and repository delivery. Library annotation is optional: Fab proposes
a `project/<slug>` tag once per project and remembers your decision. Accepted
tagging preserves filenames, content and existing tags; technical history can
stay in a hidden footer.

Markdown tables remain the default for structure and scenarios. Canvas is opt-in
and experimental. Browser prototypes check selected interactions; they do not
establish native or production readiness. Current checks include 104 regressions
and the retained beta.32 source review with five contrasting correction cases.
No additional model test was run for this maintenance release. Sustained
dialogue continuity, native behavior and external Deep Research compliance remain
open or partial; these methods do not establish retention or conversion gains.
