# Fab — brainstorm, build, ship

**Fab**, short for **Fabricator**, helps indie creators turn ideas into useful
products. Think through decisions, shape an interface, build a prototype or
prepare a release. Use one skill on its own or connect the steps your project needs.

## Use cases

- **Challenge an idea.** “Is this app worth building? Challenge my assumptions and recommend a first test.”
- **Explore possibilities.** “Suggest three approaches, explain the tradeoffs and recommend one.”
- **Review what exists.** “Audit this onboarding flow and identify the most useful improvement.”
- **Use research.** “Turn this study into decisions we can apply to our project.”
- **Shape and prototype.** “Define this feature's behavior, organize the screens and build a prototype of the critical interaction.”
- **Build a landing page.** “Use this offer and approved copy to build a responsive landing page, keeping the stack simple.”
- **Build and ship a plugin.** “Repair this skill, check its installed package and prepare a GitHub release.”
- **Continue a project.** “Recover our decisions, open questions and next useful action.”

## How Fab works

**Brainstorm:** Cowork, Research, Analysis, Brainstorm and Testing help you frame
questions, gather evidence, compare options and run focused checks.

**Build:** Product, Wireframe, Prototype and Plugin define behavior, organize
interfaces and create executable candidates or plugin packages.

**Ship:** Delivery checks feasibility, prepares handoff and organizes a release
for the agreed channel. Each skill also works independently.

## Install

Use a Codex client with plugin marketplace support:

```sh
codex plugin marketplace add iamjudin/Fab --ref v0.1.0-beta.32
codex plugin add fab@fab-local
```

Already installed? See [update and rollback](docs/install.md).

Brainstorm develops ideas through grounded critique, meaningful alternatives and
focused questions. Six Thinking Hats perspectives are optional, not a fixed answer
format. When a task grows into an independent workstream, Fab proposes a separate
chat and transfers context after your agreement, subject to host support.

## Beta status

**0.1.0-beta.32** focuses on mobile apps. Structure and scenarios use Markdown
tables; Canvas remains experimental. An opt-in screen-flow method supports task
scenarios, genuinely shared modules and caller-specific returns. One actual
file/check/correction workflow passes; earlier output misses and native rendering
limits remain. A conditional landing profile uses HTML/CSS and necessary JavaScript
for new pages without a chosen stack, preserving existing or explicit stacks.
Browser prototypes have bounded checks.
Shared interface policy now has one owner, specialized by public-site, browser
and implementation needs. Correction learning distinguishes local choices,
discovery failures, application failures and real rule gaps; significant findings
reuse the existing backlog. One fresh source-discovery review supports this bounded
behavior, not universal adoption or native reliability.
Research now plans evidence and reader presentation together, separates reusable
findings from project application and reviews returned coverage, links and numbers.
Knowledge briefs now distinguish findings from current Fab policy. The reader protects
originals and checks packet integrity. Stage reports make the next action and owner
concrete; ordinary-use dialogue consistency remains open. External Deep Research
compliance remains partial. Library use adds `project/fab`, `project/ujitsu` or
`project/once` tags while preserving existing tags and filenames. Technical usage
history stays in an optional hidden footer, outside the reader introduction.
The knowledge base adds qualified layout/typography, repository/distribution and
motivation/gamification methods. Onboarding reviews distinguish desired value,
its concrete demonstration and necessary setup. These are design aids, not
validated promises of retention, learning or conversion.
