# Fab — brainstorm, build, ship

**Fab**, short for **Fabricator**, helps indie creators turn ideas into useful
products. Think through decisions, shape an interface, build a prototype or
prepare a release. Use one skill on its own or connect the steps your project needs.

## Use cases

- **Challenge an idea.** “Is this app worth building? Challenge my assumptions and recommend a first test.”
- **Explore possibilities.** “Suggest three approaches, explain the tradeoffs and recommend one.”
- **Review what exists.** “Audit this onboarding flow and identify the most useful improvement.”
- **Use research.** “Turn this study into decisions we can apply to our project.”
- **Shape and prototype.** “Define this feature's behavior, organize the screens and build a prototype of the critical interaction.”
- **Build a landing page.** “Use this offer and approved copy to build a responsive landing page, keeping the stack simple.”
- **Build and ship a plugin.** “Repair this skill, check its installed package and prepare a GitHub release.”
- **Continue a project.** “Recover our decisions, open questions and next useful action.”

## How Fab works

**Brainstorm:** Cowork, Research, Analysis, Brainstorm and Testing help you frame
questions, gather evidence, compare options and run focused checks.

**Build:** Product, Wireframe, Prototype and Plugin define behavior, organize
interfaces and create executable candidates or plugin packages.

**Ship:** Delivery checks feasibility, prepares handoff and organizes a release
for the agreed channel. Each skill also works independently.

## Install

Use a Codex client with plugin marketplace support:

```sh
codex plugin marketplace add iamjudin/Fab --ref v0.1.0-beta.35
codex plugin add fab@fab-local
```

Already installed? See [update and rollback](docs/install.md).

Brainstorm develops ideas through grounded critique, meaningful alternatives and
focused questions. Six Thinking Hats perspectives are optional, not a fixed answer
format. When a task grows into an independent workstream, Fab proposes a separate
chat and transfers context after your agreement, subject to host support.

## Beta status

**Current version: 0.1.0-beta.35.** Mobile apps are the current focus, not a
product-size ceiling. Skills work independently; websites and landing pages have
conditional routes.

This release improves opt-in Canvas flows: visible screen content and context,
stable reader numbers, consistent project legends, current-map navigation and
forward column layout. Commands require their own action/outcome; reused module
calls require connected caller continuations. Existing research, correction
learning and interface principles remain available without a compulsory pipeline.

A corrected raw-input-to-Canvas candidate is accepted as a working foundation.
A selected path also runs as a checked browser prototype. Original failures and
corrections remain recorded; this is not a clean-first-pass or general reliability
claim. Canvas remains experimental and tables remain the default. Browser evidence
does not establish native or production readiness. Further quality assessment
comes from actual project work; no automatic model suite is implied.

The deferred knowledge-base migration and test products are excluded from this
release. Library tags remain optional and additive, with one project-level choice;
source names, content and existing tags are preserved.

and [validation evidence](experiments/releases/canvas-beta35-20261026/report.md).
