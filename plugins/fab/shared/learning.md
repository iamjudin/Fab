# Learn from corrections without accumulating rules

Read for a consequential correction, recurring failure, conflicting guidance or
proposal to change reusable instructions. A typo, accepted local preference or
completed small edit does not require a lesson document, new backlog item or
rule review. Use the existing project records and actual edit authority.

## Locate the cause before choosing the scope

Inspect the requested outcome, actual artifact/version, expected versus observed
behavior and governing instruction. Keep facts, interpretation, preference and
unknown cause distinct. Find the current owner and read trigger before adding text.

| What the evidence shows | Smallest sufficient response |
| --- | --- |
| A one-off defect, content choice or accepted local preference | Correct the authorized artifact; retain a project decision only when later work needs it. Do not make it universal. |
| An applicable rule exists but was not found | Repair its discovery/read trigger or stale reference at the owning entry. Do not duplicate the rule in every skill. |
| The applicable rule was read but not applied | Inspect the execution/preflight seam and a relevant output case. Another copy or stronger wording is not evidence of a repair. |
| The rule is ambiguous, contradictory or lacks a necessary condition | Clarify the canonical owner and affected consumers; preserve valid exceptions. |
| A repeated or causally clear gap spans relevant contexts | Propose the narrow reusable distinction, its applicability and a countercase. Edit only within actual authority. |
| Evidence, environment, tool or test setup is inadequate | Qualify the claim or repair that setup. Do not convert an unverified symptom into a product prohibition. |

Recurrence is a signal, not a quota. One clear contradiction of an accepted
invariant can justify repair; many similar outputs do not establish the same
cause or a universal rule. A requested preference is valid for its agreed scope,
not population evidence. Research uncertainty may need the existing relevant
[method](methods/index.md), a focused investigation or [test](../skills/testing/SKILL.md),
not an invented restriction or an automatic new external run.

## Put a change with its real owner

Keep a decision with the artifact/project when it concerns that project's content,
behavior or accepted choice. Use an existing scenario/platform reference for its
specific conditions. A reusable meaning belongs with its existing current owner
and source limits; its brief routes there. Where no maintained meaning store
exists, use the actual existing evidence owner. An instruction about authoring
belongs with its capability/reference.
Only a genuinely cross-capability principle belongs in shared policy. Source
findings, current policy, local application and observed execution stay distinct.
Do not rewrite a preserved source packet to make it agree with a new instruction.

Prefer changing/linking the canonical owner over creating another catalogue,
per-task memory file, skill, checklist or profile. Guidance may link to relevant
existing evidence without importing full logs or private examples into runtime.
Do not make a project case a plugin dependency. For a knowledge-organization gap,
check owner, applicability, source basis, read trigger and affected consumers;
these are reasoning questions, not mandatory new fields on every artifact.

## Verify and retain proportionately

For a meaningful unresolved or reusable finding, reuse its owning backlog item or
existing project decision. Record the original observation and version, cause with
confidence/unknowns, scope, proposed or actual change, owner, next check and closure
boundary. Use the project's existing statuses; do not open a competing learning
queue. Preserve failures alongside corrections, and distinguish proposed,
implemented and actually verified outcomes. Fixed source is not installed behavior.

Check the mechanism changed: discovery needs an observed appropriate read;
application needs an output using the distinction; implementation needs its actual
behavior. Use the failure or an equivalent case plus a contrasting valid case when
it can expose overgeneralization. File/link checks prove integrity, not semantic
use or user value. Select a bounded test only when needed and authorized; ordinary
preflight and real-use evidence may suffice. Stop when the promised scope is checked.

Promote only supported, useful changes, retire superseded guidance at its owner,
and review affected consumers when meaning changes. Do not silently invalidate
unrelated accepted work. A finding does not authorize editing a plugin, global
instructions, another project, installation or publication. Continue the authorized
local result while routing an out-of-scope reusable proposal to its actual owner.

## Close the migration, not only the addition

When consolidating existing knowledge, the outcome is one effective current
meaning, not a second explanation layered over the first. Before marking a
meaning migrated, switch its active consumers, remove its competing working
paraphrases and check preserved applicability, exceptions and source identity.
A brief can remain an entry/coverage pointer; explicitly unmigrated knowledge
can remain until reconciled. Original source evidence is provenance, not a
competing default authority. Do not delete uncovered knowledge to make cleanup
appear complete, or declare an entire topic migrated from a few covered units.


Before closing a whole topic, account for its substantive remainder in the
existing audit/report: current meaning (including enrichment of an existing
owner), deliberately reference-only detail, superseded advice or an explicit
unresolved gap with a next action. A few valid units do not establish topic
coverage. Do not call unreviewed reusable knowledge reference-only merely to
finish. Choose incremental scope to preserve progress, not to lower the promised
quality or leave an unexplained set of fragments. Research verification,
source reconciliation, practical application and distribution remain distinct
completion claims; unresolved source quality must stay visible.
