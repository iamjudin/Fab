# Landing pages and compact public sites

## Active object and scope

Use for a public promotional/offer page or a compact service site. Route by the
current visitor task and object, not the word landing, browser platform or page
count. A site can have two audience views or a few supporting pages without
becoming a prescribed funnel or an application. Do not project marketing rules
onto an app entry screen or unrelated work in the same project.

Treat an existing site's pages, documents and screenshots as input, not a mandate
to preserve its structure. Retain accepted content/brand decisions and rebuild
only the requested scope. Page count and composition follow actual visitor needs;
do not force a one-page strip or a replica of every archived page.

## Separate concerns; use only the active layer

[Shared interface principles](interface-principles.md) own reusable meaning,
grouping and role economy. This public-site scenario does not duplicate them.

- For public-page meaning, copy and section purpose, read
  [web content](web-content.md): concrete explanation, supported claims, useful
  headings/actions and no filler written to satisfy a template.
- For visible composition and typography, read
  [web layout](web-layout.md): semantic grouping, economical text roles and real
  adaptation. These principles do not depend on HTML/CSS or a framework.
- For actual technical implementation, read
  [web implementation](web-implementation.md): plain web first for an uncommitted
  stack, existing-stack preservation, actual dependencies and readiness.

Product owns missing offer/visitor/action meaning; Wireframe owns section
hierarchy/composition; Prototype owns selected executable experiments; Delivery
owns actual implementation; Analysis owns review. Cowork can orient. Accepted
inputs permit direct entry; no eleventh skill, obligatory interview, full product
graph, canvas, gray stage, fixed section sequence or Figma/code round trip.
Actual domain/navigation complexity still needs sufficient behavior modeling.

Check the requested result. Useful copy does not prove rendered readability;
a screenshot does not prove comprehension, backend delivery or conversion.
Do not claim all three layers were applied merely because their files were read.
Keep creator choices, observed evidence and assumptions distinct.
