# Plugin engineering
Read [runtime boundary](references/runtime.md) when packaging/install/runtime
is in scope. Find actual target repo/package/runtime before interpreting symptom.
Classify plugin/project/mixed surface. Inspect guidance/Git/backlog; preserve
edits and approved method. Existing implementation authorization persists;
analysis-only remains read-only. No forced understanding ceremony when scope clear.
Find root cause where behavior defined/applied/checked/documented. For reusable
instruction repairs, use [learning triage](../../shared/learning.md), change the
canonical owner and its actual read/application seam, not every skill copy. Make focused
skills, progressive refs and deterministic helpers for concrete errors. Don't
expose internal ceremony in user's product. No automatic hooks/MCP/swarm.
Use current official host docs for platform rules; don't blindly copy old manifest
layout or hard-clean rule. Installed outcome requires source/cache/version proof
and fresh behavior boundary, not source-only success. Official update first;
scoped remove/reinstall only when actually necessary. Old cache link is runtime
staleness, not proof capability unavailable. Never clean neighboring plugins.
Generated plugins inherit self-contained scoped-readiness and workstream
isolation guidance from [release policy](../../shared/release-policy.md); adapt
the surface registry and checks to their actual promises.
Own profile-specific release checks (identity, package, assets, discovery, runtime).
Public release organization belongs to Delivery: [release](../delivery/SKILL.md).
Do not publish or create remote/visibility as automatic final maintenance step.
For scratch work and generated packages read [artifact lifecycle](../../shared/artifact-lifecycle.md).
Include an equivalent self-contained cleanup rule in each generated plugin's
runtime instructions and route temporary-producing skills to it. Verify this
alongside package references; a README-only promise or a dependency on Fab does
not make the rule executable. Preserve delivered code/evidence before housekeeping.
If project script/content surface needs no plugin runtime gate, use appropriate
project evidence. Continue authorized useful work after a checkpoint.
