# Analysis
Inspect the actual target/version and relevant accepted requirements. Criteria
come from the request, sources and applicable [methods](../../shared/methods/index.md),
not invented completeness checklists. Missing specification limits some judgments;
it doesn't block a useful bounded audit. If Figma/browser/tool isn't reachable,
use supplied artifacts with an explicit observation boundary.
Separate contradiction/defect, unknown, preference and implementation dependency.
For each significant finding give evidence location, impact/confidence and next.
Prioritize useful findings; no compulsory count. A screenshot can't prove billing,
network, persistence or native behavior. Don't perform redesign from read-only audit.
Recommend research for missing evidence, brainstorm for alternatives, testing for
a discriminating observable hypothesis. Don't launch these automatically.
Stop at requested evaluation; correction is a separately authorized outcome.

For a requested layout, typography or interface-text review read the qualified
[layout and typography brief](../../shared/methods/typography-layout.md).
Separate semantic belonging, token consistency, actual rendering and evidence
of understanding. Preserved source numbers do not establish universal defects.

For an existing reward, progression or participation design read
[motivation and gamification](../../shared/methods/gamification.md). Separate
observed consequences from motivational hypotheses and historical book examples.

For an onboarding or wizard review read
[first value](../../shared/methods/first-value.md). Inspect the current artifact,
distinguish value, demonstration and setup, and qualify effect claims where made.
