## Findings

### 1. Citation loss predates Refine, and partial repair is not research closure

The original Downloads export contains68citation-marker occurrences and **zero
literal URLs**. A marker such as turn…search… is an internal identifier, not a
portable source address. The original export SHA-256 is
`5d30f64217c5ccf17f00230dfd00aa9cda325b7ebda2c9c16422bbc13aeacabf`.
The Brain report states that56occurrences were replaced with title-links and12
removed without reconstructing an address, while retaining nearby claims.
These are occurrences, not68distinct sources or12distinct missing studies.

The separate Refine chat confirms receiving the marker-only source and attempting
claim-based source recovery. Its installed contract explicitly permits removing
an unresolved marker while retaining the claim with a disclosed limitation. Thus
it is inaccurate to blame Markdown itself, claim that Bookworm lost68working URLs,
or describe the cleaned note as independently reverified. Newly found relevant
support is not necessarily the original source behind an internal identifier.
The export mechanism that produced the original file was not inspected.

Fab's existing Deep Research output contract already asks for descriptive links
and forbids raw markers. The demonstrated gap is checking/enforcing the actual
returned artifact, not the absence of that prompt instruction. A source export
with unresolved addresses should retain a claim-level unresolved map alongside
its original. Known supported material can still be used with an honest scope.
Do not silently promote affected empirical claims into qualified shared truth.
The missing structural-comprehension CHI citation is one concrete unresolved
example. The preserved report's12unresolved occurrences have not all been
independently identified and restored in this audit.

The Refine run directory is no longer present after verified handoff. Its final
output and original source survive. This audit has not recovered a durable full
claim-to-marker ledger from that run. Retention of unresolved provenance is a
follow-up condition, not authority to modify Bookworm from this Fab task.

### 2. Existing principles are present, but some practical distinctions are thin

The ordinary current bodies already cover Atomic Design as a parts/whole model,
sufficient token layers, role reuse, domain/core boundaries, state ownership,
context combinations, code/design transforms, identity, recovery and migrations.
They explicitly reject a mandatory atomic tree, fixed reuse threshold and full
variant Cartesian product. This audit does not justify rebuilding the base or
adding a second architecture catalogue.

The new report adds useful discriminating explanations that are not comparably
explicit in the current bodies: why a frame can inherit safely through its parent
without its own master, when an internal Base actually removes multiple edit
points, bounded swaps versus consumer-owned slot content, public versus internal
library assets, and source masters versus linked documentation specimens.
Enrich the existing owners instead of duplicating report summaries.

### 3. Concrete discovery terms miss existing relevant bodies

The bundled lexical reader returns no units for `вложенность`, `слоты`,
`instance swap` and `извлечение`. `slot` does find component-contract and `variants`
finds context-axes. Broader component queries also find useful owners and some
unrelated metadata matches. This is bounded evidence of vocabulary gaps, not proof
of failed semantic/embedding search or absence of the knowledge itself. The reader
is documented as lexical and offers index/brief fallback.

Add grounded aliases/triggers to the enriched owners. Validate exact queries and
read the returned full body, not just the number of results. A lookup pass does
not establish that an agent will apply the content well.

### 4. Architecture endorsement needs a consumer/change comparison

The style-chat actor actually reads current system-reuse and component-contract,
then promotes the supplied Content/Master/Style example too early. The creator
corrects it and the actor withdraws the recommendation. Existing cautions were
found but not sufficiently applied. Proposed repair belongs at the canonical
assessment-to-recommendation seam: compare consumers, a simpler valid construction,
one real future edit and override/migration cost before recommending extraction.
Do not add a universal maximum nesting depth or require renewed approval of every
frame. A justified existing deep architecture remains a valid countercase.

### 5. Technical examples need version and environment boundaries

Primary spot checks support the report's central distinction between documented
configuration mechanisms and architecture choices:

- [Brad Frost's methodology](https://atomicdesign.bradfrost.com/chapter-2/) supports
  concurrent parts/whole reasoning. It does not prescribe a Figma-master tree.
- [Figma's swap/slot comparison](https://help.figma.com/hc/en-us/articles/38741465279895-The-difference-between-slots-instance-swaps-and-variants)
  distinguishes constrained replacement and free composition. That supports the
  choice distinction, not a mandate to use slots in every library.
- [Figma's migration guidance](https://help.figma.com/hc/en-us/articles/38607529833751-Migrate-a-library-to-using-slots)
  warns that migrating shared placeholders may lose customized overrides. Inspect
  actual consumers before migration. Local workspace/API access was not tested.
- [Figma's variable overview](https://help.figma.com/hc/en-us/articles/14506821864087-Overview-of-variables-collections-and-modes)
  lists six product-level variable types, with Timing/Easing tied to Motion.
  This does not establish that each is available through the active Plugin API.
- The report's [React Code Connect page](https://developers.figma.com/docs/code-connect/react/)
  now labels framework-specific parsers legacy and unsupported for further updates.
  The semantic mapping example remains explanatory. For actual implementation,
  use the current [template-file documentation](https://developers.figma.com/docs/code-connect/template-files/)
  after checking the target environment, rather than shipping a legacy recipe.
- [WCAG target-size guidance](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum)
  retains its browser units and exceptions. No universal native/web hit-size number
  or accessibility certification is inferred.
- [The Way We Notice](https://arxiv.org/html/2602.22436v1) concerns component variation
  and Storybook authoring. It is not a substitute citation for an unidentified
  Figma structural-comprehension study or a measured optimal nesting depth.
