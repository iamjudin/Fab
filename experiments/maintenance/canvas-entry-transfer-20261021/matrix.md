# Input diversity and evidence boundaries

The former Canvas workstream evaluated these eight classes by authored tabletop
responses. Main has read the actual creator clarification and source dossiers.
The input axis is requests **to Fab**, not entry screens inside one application.

| Prior class | Integrated capability question | Fresh priority / limit |
| --- | --- | --- |
| VE01: raw idea | Product framing under Cowork/shared authority; no premature map | DV01 fresh PASS for bounded framing; no maps or invented acceptance |
| VE02: sufficient one-screen brief | Direct Wireframe and bundled screen-flow; conditional NAV/MOD | DV02 fresh PARTIAL: semantics/proportion pass; fallback text visibly overflows one card |
| VE03: multiple roots and actual reused behavior | Wireframe composition plus known child/parent commit policy | DV03 attempted; timed out before any complete candidate, semantics unassessed |
| VE04: accepted model and monolithic map | Preserve identity while reorganizing | Source contract assessed; full reorganization deferred, not counted as observed generation |
| VE05: partial visual correction | Preserve unaffected source, restrict edit scope | DV04 prepared but not launched after timeout/unknown-usage campaign stop |
| VE06: screenshot-only audit, no edit | Analysis instead of a redraw; distinguish visible and unknown | Current Analysis route read; screenshot behavior deferred to an actual supplied visual case |
| VE07: stale taxonomy versus latest agreement | Honor current agreement and conditional taxonomy | Active integrated Wireframe/reference clauses inspected; no multi-turn recovery result claimed |
| VE08: accepted artifacts, executable prototype requested | Direct Prototype; no forced map rebuild or native readiness | Prototype route read; executable/browser test deferred, not part of this Canvas campaign |

The four selected fresh cases vary domain, maturity, topology and edit authority.
They do not cover every input combination, native runtime or full large-product
execution. A bounded map bundle may support a later full task/review iteration;
the campaign does not declare a virtual operator to be the actual creator.

Already observed local-search misses remain controls for output inspection, not
an excuse to force every new case into search, scroll position or chat drafts.
Known source already requires compact action cards and meaningful recoveries;
do not add policy or a new engine before locating the different inputs' actual gaps.
