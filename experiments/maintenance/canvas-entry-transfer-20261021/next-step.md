# Proposed next acceptance: actual artifact workflow

This is a prepared recommendation, not execution authorization or a new campaign.

## Decision

Test whether the unchanged integrated method can deliver and self-check a useful
artifact in a normal isolated work area. The current read-only JSON-envelope
campaign observes source selection and first-output generation; root creates
files and runs checks afterward. It does not exercise the skill's own actual
file-generation / validator / preview / correction loop. A fit miss in that
environment is not sufficient grounds to add more policy to existing instructions.

## Bounded setup

- Retain the actual frozen89-file source and accepted inputs as read-only. Use
  a separate task-owned writable output directory for candidate artifacts only.
  Protect main, installed runtime, other projects and live vault; verify hashes.
- Reuse the workshop request already defined in DV03, whose shared-client and
  child/parent commit question remains unassessed. Do not supply a desired map,
  author builder or preselected decomposition. Discover actual skills as before.
- Ask for the actual requested candidate, permit bundled file/registry/Canvas
  checks and source-owned fallback, and let the actor correct its own output
  before handoff. Freeze source during the check. Record intermediate failures
  and tool interventions; do not convert a corrected result into an original PASS.
- Root inspects the retained bundle, paths, caller-specific returns, independent
  commits, error/retry and actual fallback overview/detail. Native Obsidian,
  participant value and scalability remain separate unknowns.

## Budget and authority

Do not reuse the closed campaign's unused fourth slot or reset the budget. DV03
has unknown token usage, so the campaign total is unknown. Select an explicit
bounded execution/time/token forecast that accounts for that pilot and the
different writable-output workflow before launching. No automatic retry or
unbounded workshop build. Actual permission for that writable isolated test and
its budget is still needed; no source repair, installation, Git or release is
included by this proposal.

## Repair decision after evidence

If actual self-check misses overflow or unbound local continuation again, repair
the specific application/check boundary in Wireframe and verify that bounded
change. Existing instructions already require both. If output validation catches
and corrects the issue, retain that evidence rather than adding duplicate rules.
If the method still cannot deliver within the bounded run, separate execution /
budget design from a demonstrated missing product or representation rule.
