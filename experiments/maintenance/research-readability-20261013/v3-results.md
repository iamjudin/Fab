The current Fab contracts already require these behaviors. Enforce actual output
review and explicit partial status, preserve originals and separate follow-up work.
A changed recommendation or longer report is not better supporting evidence.

Add HTML tables, dense introductions, repeated records and broken navigation to
Bookworm's structural fixture classes. Source repair and calculation correction
remain explicit substantive scopes, not silent Refine edits. This external report
does not validate Bookworm Digest/Enrich behavior.

Recommend retaining this comparison and proceeding with the prepared Bookworm
engineering task when transfer is explicitly authorized. Do not launch another
full external rerun automatically. A project application may retain hypotheses
and limitations, but should not turn unsupported recommendations into accepted
strategy. Source verification and corrected models would be prerequisites for
substantive strategic use.
