# Host-level research format conflict

The first Fab beta.25 source probe reads the new Research contracts but still
inserts the old literal footer. The active global AGENTS requires that footer
verbatim. The result contains contradictory punctuation instructions. This is
a host-policy conflict, not a demonstrated failure to read the new references.

## Proposed replacement for the global formatting section

- When preparing a Deep Research prompt, follow the creator-approved active
  project/skill reader contract and requested report language. State the research
  question, relevant conditions, evidence scope, presentation plan and limits.
- Produce clean Obsidian Markdown with meaningful headings, descriptive source
  links, compact comparison tables, lists for independent items and short causal
  explanations. Preserve evidence, qualifications and detailed-source access.
- Do not require the former literal footer. Do not use semicolons in newly
  authored reader text. Preserve exact source quotations and code punctuation.
- Keep diagrams editable and check actual note-width readability. Prefer a table
  or list where sufficient. Review coverage, source support and conditional
  numerical consistency. Report unresolved gaps rather than claiming compliance.

This changes only the host's research formatting section. All unrelated global
instructions remain unchanged. A scoped project exception is the alternative,
leaving the old global requirement active elsewhere. Creator choice is needed
before a global setting edit. No host setting has been changed by this proposal.

## Creator-approved final scope

Creator authorized the global change, then questioned whether global formatting
is needed. Adopt only a neutral active-project/skill routing instruction. Do not
duplicate the reader contract globally or remove unrelated global Git/backlog
habits. The original global footer is backed up privately, other sections are
byte-preserved. This is a host-specific correction, not part of the portable ZIP.
