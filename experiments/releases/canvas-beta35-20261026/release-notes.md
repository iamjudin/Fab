# Fab beta.35 — readable Canvas flows and executable handoff

Opt-in Canvas authoring now preserves visible screen composition and context,
stable reader addresses, compact complete project legends, current navigation,
column-local placement and section dividers. Conditions and service events share
yellow; all legend roles use consistent swatches.

Explicit user commands need their owning action and represented outcome. Invoked
modules need a local continuation: a prose promise and disconnected results cannot
stand in for a readable chain. Input, local effects, unknown behavior, system
updates and actual user commands remain distinct. Shared modules retain their
caller-specific context; return links replace backward connector spaghetti.

The creator accepts the corrected raw-input workflow as a working foundation.
A selected path is implemented and observed in a browser prototype without new
business policy. Initial failures, corrective interventions, timeout and unknown
usage remain evidence, not a clean-first-pass/general reliability claim.

Canvas remains opt-in experimental; tables remain the default. Native rendering,
whole-product coverage, real server deduplication and file/OS persistence are not
certified. The next step is observation during real work, not another generic
suite. No new automation is created or retargeted.

The package contains95files and differs from tested local .20261026.12 only in
manifest version. Deferred knowledge migration, design-system intake, test products
and heavy raw runs are excluded. Approved identity and icon remain unchanged.
