# Fab: частичные задачи и связки · контракт 2026-10-12

## Решение и гипотеза
Проверяем сам Fab как полезный продукт для инди-создателя: достаточно ли прямых
навыков и коротких связок для мнения, вариантов, оценки существующего решения
и ограниченной доработки без обязательного маршрута до прототипа.
Работа авторизована автономно; creator допускает расход 2–3 пятичасовых окон при
необходимости. Это запас, не цель использования и не разрешение на credit reset.
Экспериментальная ветка codex/partial-workflow-tests, без merge/public release.

## Метод и границы
Baseline167c6be, установленный beta.15,60files/cf1d23be54742d51, source/cache PASS.
Каждый primary — свежий codex exec в отдельном task-owned workspace вне Fab repo;
основная переписка, maintainer docs/Brain и ожидаемые ответы не передаются.
Обычная конфигурация CLI остаётся; фактические model/effort проверяются по rollout.
Это не тест чистой установки или автоматического discovery без указания entry.
Root оценивает исходники/события/ответы без edits к наблюдаемому baseline; это
оценка разработчика, не независимый human acceptance или рынок. Подсказки
исправлений не входят в primary; corrective получает отдельный вход и версию.
Персональные решения оператора в fixtures синтетические.

## Различающие случаи и критерии качества

| Случай | Вход / маршрут | Полезный исход и различающий сигнал |
| --- | --- | --- |
| opinion | новая чрезмерно широкая app-идея → Cowork | Собственное обоснованное мнение; проверяет конфликт масштаба/срока/ресурса, полезное направление, без рыночных выдумок, преждевременного PRD/кода или подмены автора. |
| ideas | ограниченная творческая задача → Brainstorm | Различные механизмы возвращения к истории, не пять названий одного редактора; tradeoffs и выбор первой проверки. Без AI/push/streaks/social и ложного принятия решения. |
| audit | принятые правила + HTML → Analysis | Доказательная приоритизация реальных дефектов; read-only. Fixture допускает проверку глобального счётчика, мутации редактируемой записи до Save, потери draft и нового item до успешного persist/retry. Не объявляет фактические UI наблюдения по одному чтению кода. |
| audit-options | описание решения + малые наблюдения → Cowork/Analysis/Brainstorm | Объясняет причину потери данных/непонятного commit; варианты различаются механизмом, рекомендация сохраняет общий список/ручное подтверждение. Четыре попытки не доказывают prevalence/рынок. Без полномасштабного redesign. |
| feature | accepted model + Undo → Product | Достаточное bounded поведение: какие успешные действия отменяются, scope/expiry/повторы, фильтр/поездка/ошибка; candidate decisions и неизвестные явно. Не создаёт искусственный полный Jobs/экранный pipeline и не меняет прежние правила. |
| wireframe | существующие model/interface/map → Wireframe | Адресная согласованность проекций: повторяемые owners, branch-specific create/save/cancel/error return. IDs/model остаются прежними, runtime guards проверяются, код/prototype не создаётся. Это focused transition из существующего evidence WF-01/FAB-03, не fresh full route. |
| evidence-slice | три эпизода наблюдений → Cowork/Research/Product | Evidence/интерпретация/гипотеза разделены; вывод не «всем нужен план», counterexample сохранён. Один ограниченный кандидат с проверяемым вопросом, без AI/соцсети и ложной эмпирической валидации. |
| ideas-followup | поправка оператора в той же сессии | Не пересоздаёт задачу; сохраняет уточнённый выбор/открытые варианты и даёт полезную следующую проверку. Только один synthetic follow-up, если pilot показывает полезность проверки continuity. |

Сквозная оценка: полезность решения, основание и уверенность, сохранность смысла,
соразмерность маршрута, содержательный итог/next. Нет обязательного количества
findings, файлов или вызовов навыков. Модель может выполнить связку сама, если
результат достаточен; чтение всех SKILL не заменяет качества. PASS допускает
ограниченные замечания, существенный дефект получает отдельный expected→observed.

## Бюджет и остановка
До7primary,1follow-up,3адресных corrective и1условного diagnostic: максимум12turns.
Прогноз aggregate≤5M input/150k output, после pilot уточняется; cached input не
процент аккаунтного лимита. ≤600s/turn,≤75min активных runs; не более2параллельных
запусков после оценки pilot. Никаких повторов ради числа PASS.
На существенном провале прекращаем тот case, сохраняем baseline и triage; не
подправляем его в середине. Остальные случаи продолжаются только с новым сигналом.
При исчерпании окна — сохраняем checkpoint; reset/покупок нет. Остаток допускает
естественное обновление окна, если дальнейшая работа ещё даёт полезный результат.

## Сохранение и результат
Prompts/малые fixtures/ответы/meta/observer/report сохраняются в
partial-routes-20261012. Полные logs/frozen workspaces/runtime — ignored raw archive;
SHA исходников/outputs и actual usage/time сохраняются. Scratch строго
/private/tmp/fab-partial-routes-20261012; после проверенного переноса убрать только
его. Изменения Fab при подтверждённом дефекте — отдельный checkpoint/version,
затем focused corrective; не объявлять первоначальный run чистым.
Итог объясняет пригодность частичных маршрутов, где ещё нужен контроль, наше
мнение и лучший следующий шаг; findings обновляют owning backlog без дублирования.
