# Интерфейсный кандидат

Корректирующая сверка: 2026-10-12, установленный Fab 0.1.0-beta.16, Wireframe. Основание — [model.md](model.md), UC-01–UC-06, DR-01–DR-03 и существующий кандидат. [structure.canvas](structure.canvas) — карта структуры и доступа, не макет экранов. Модель и статус candidate сохранены; creator approval отсутствует. Целевой native-платформы модель не задаёт; browser dialog остаётся текущим интерфейсным кандидатом.

## Структура и владение

S-01 — корень navigation stack «Поездки», обычный вход в приложение. Заголовок и список поездок; внутри списка каждая повторяемая поездка владеет названием, счётчиком «собрано X из Y» и открытием S-02 с её ID. «Новая поездка» принадлежит экрану и открывает S-03 в режиме создания поездки. Пустой список сохраняет этот вход. Переименование и удаление поездок в срез не входят.

S-02 — выбранная поездка: Назад→S-01, полное название, «собрано X из Y», локальный переключатель Все/Осталось и список вещей этой поездки. Внутри списка повторяемая вещь владеет названием, состоянием packed, отметкой/возвратом и открытием правки S-03 с ID вещи и поездки. «Добавить вещь» принадлежит поездке и открывает S-03 с её ID. Нет смешивания поездок. При обычном открытии выбранной поездки фильтр — «Все»; при browser reload восстанавливаются last-trip и фильтр согласно допущениям модели.

При успешной отметке в «Осталось» вещь исчезает из отфильтрованного списка. Существующий механизм возврата через feedback сохранён как действие S-02, связанное с конкретной отмеченной вещью; альтернатива — «Все» и отметка в строке этой вещи. Feedback не является массовым действием или отдельным экраном. Его точный вид и длительность доступности исходниками не определены; здесь они не переопределяются. Возврат, как и отметка, запрашивает запись и подтверждается только после её успеха.

S-03 — временная modal form с явным родителем и тремя режимами: новая поездка из S-01, добавление вещи из S-02, правка вещи из S-02. Заголовок отражает режим; label и поле названия, inline error, Отмена и Создать/Сохранить принадлежат форме. При создании поле пустое, при правке содержит исходное название. Клик вне формы не закрывает её; Escape равен Отмене. Это browser dialog, native sheet не доказан.

Нет tab bar: независимых верхних разделов нет. Приоритет в S-02 — остаток и добавление, затем правка; это сохранённое решение кандидата, не доказанная частота использования. На карте отдельно показаны коллекции и повторяемые объекты; стрелки означают переходы и результаты записи, а не композицию.

## Доступ и возврат

| Действие | Владелец / контекст | Результат и возврат |
| --- | --- | --- |
| Открыть поездку | Строка поездки в S-01 | S-02 с выбранным Trip.id, фильтр «Все» |
| Новая поездка | S-01 | S-03; успешное создание → S-02 новой поездки; Отмена/Escape → S-01 |
| Назад | S-02 | S-01, без изменения вещей |
| Все / Осталось | S-02 | Локальная смена представления той же поездки |
| Отметить / вернуть | Вещь в S-02 | Запись packed той же вещи; остаёмся в S-02 |
| Вернуть через feedback | S-02, конкретная вещь | Обратная запись packed; остаёмся в той же поездке и фильтре |
| Добавить вещь | S-02, выбранная поездка | S-03; успешное создание или отмена → тот же S-02 и фильтр |
| Править вещь | Строка вещи в S-02 | S-03 с исходным названием; сохранение или отмена → тот же S-02 и фильтр, ID вещи сохранён |

Отмена откатывает только черновик и ничего не записывает. Создать/Сохранить возвращает из формы только после успешной записи. После создания поездки результатом является S-02 новой поездки, хотя родителем формы был S-01; эта ветка отличается от отмены. Начальные поля создания и редактирования согласованы с моделью: название, без категорий, шаблонов и новых настроек.

## Сценарии и правила

Основной сценарий: пустой S-01→S-03 создания поездки→успешная запись→S-02→S-03 добавления вещи→успешная запись→отметить→Осталось→вернуть через feedback/Все→Назад→вторая поездка→вернуться в первую→reload. Ожидается сохранённый прогресс, восстановленные last-trip и фильтр; это требование кандидата, а не результат запуска приложения.

Правка: S-02→S-03 с исходным названием→изменить→Отмена/Escape→исходное сохранено; повторить→Сохранить→после записи новое имя с прежним Item.id. Поездка и фильтр возврата сохраняются.

DR-02: trim; пустое/пробельное название→inline error и focus на поле; дубликаты разрешены, ограничения длины не вводим. Черновик отделён от подтверждённых данных. Длинный текст должен переноситься, не выталкивая действия; пустая поездка, отсутствие остатка («Всё собрано») и пустой список поездок различаются.

DR-03: ошибка записи→форма остаётся с вводом и сообщением, прежние данные не меняются; повторить→одна подтверждённая запись. Ошибка отметки или возврата→предыдущее packed и сообщение, без ложного подтверждения. Ошибка чтения→блокирующее сообщение без стирания или перезаписи повреждённых данных. Ошибки и повтор не требуют новых поверхностей; на обзорной карте показано место сообщения формы, детальные ветки остаются здесь.

UC-01 покрыт S-01, открытием S-02 и созданием через S-03; UC-02 — добавлением из S-02 через S-03; UC-03 — правкой из строки вещи; UC-04 — отметкой/возвратом и feedback; UC-05 — Все/Осталось и прогрессом; UC-06 — возвратом к поездке и восстановлением при reload. DR-01 соблюдается владельцами и передаваемыми ID; DR-02/DR-03 — правилами формы и записи выше.

## Результат сверки и проверка

Причина расхождений — неполная проекция существующего кандидата: плоские строки поездок, отсутствие коллекции вещей, сводки S-02, feedback и веток выхода S-03. Исправлены карта и её описание, сохранены все исходные IDs узлов и рёбер. Новые IDs обозначают недостающие контейнеры, информацию, feedback и возвраты; существующие взаимодействия не удалены. Убрано неподтверждённое утверждение о показанных блоках в `blocks.html`: этого файла в текущей папке нет.

Проверки Fab beta.16: `check_structure.py reviews/structure.canvas --surface-id S-01 --surface-id S-02 --surface-id S-03` — физическое владение проходит; `product_workspace.py validate-canvas product reviews/structure.canvas --vault-root /private/tmp/fab-partial-routes-20261012/wireframe-corrective` — JSON и ссылки проходят. Для первой команды путь указан относительно `product`, для второй — относительно корня проекта. Дополнительно проверены уникальность IDs, вложенность коллекций/элементов, наличие всех исходных переходов и соответствие таблице доступа. Fallback `canvas_preview.py` → SVG: без предупреждений о пересечениях содержимого, заголовках групп и переполнении текста.

Регистрация Canvas не выполнялась: отдельный registry вышел бы за разрешённые два артефакта. В Canvas нет файловых узлов; указанный vault root — корень проверки, фактическое открытие в Obsidian и его геометрия не проверены. Fallback не доказывает native rendering. Прототип, запись в storage, usability, accessibility и native/device review не запускались. LocalStorage одного browser origin по модели не означает backup, перенос или native lifecycle; CSS размеры не объявляются эквивалентом iOS pt.

Результат достаточен для сверки структуры и сценариев этого среза. Точный вид feedback остаётся деталью кандидата для последующего интерфейсного решения; он не служит причиной удаления механизма или изменения модели.
