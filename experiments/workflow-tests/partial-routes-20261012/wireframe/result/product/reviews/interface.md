# Интерфейсный кандидат

Сверка от 2026-10-12: установленный Fab 0.1.0-beta.15, навык wireframe. Основание — [model.md](model.md), включая UC-01–UC-06, DR-01–DR-03 и candidate assumptions. Модель не изменена; статус интерфейса остаётся candidate, реального creator approval нет. Эта работа ограничена описанием и [structure.canvas](structure.canvas); это карта структуры, не прототип и не доказательство поведения реализации.

## Структура и владельцы

**S-01 — «Поездки», корень navigation stack и основной вход.** Заголовок, список поездок и «Новая поездка». Список содержит повторяющуюся строку поездки: название, «собрано X из Y» и открытие именно этой Trip.id в S-02. Открытие принадлежит строке, создание — экрану. Пустой список предлагает создать поездку. Переименование и удаление поездок не входят в SL-01.

**S-02 — выбранная поездка.** Назад→S-01, полное название, общий прогресс «собрано X из Y», локальный переключатель «Все / Осталось», список вещей и «Добавить вещь». Список вложен в поездку; повторяющаяся вещь владеет названием, packed, отметкой/возвратом и правкой конкретной Item.id. Отметка сразу запрашивает сохранение, поэтому зелёная; это не черновой checkbox. Фильтр голубой: меняет представление текущей поездки, не её вещи. Прогресс считается по всем вещам поездки, независимо от фильтра.

«Добавить вещь» принадлежит S-02, а «Править» — вещи. Обе команды открывают S-03 с Trip.id, правка дополнительно передаёт Item.id. Фильтр не смешивает поездки. Отдельные dashboard, tab bar, настройки и экран вещи для этого среза не нужны: все операции с вещью помещаются в её строку и временную форму.

**S-03 — временная modal form с источником открытия и целевым объектом.** Заголовок режима, label/поле названия, место сообщения об ошибке, Отмена и кнопка записи. Это browser dialog; native sheet и платформенное поведение не проверены. Клик вне формы не закрывает её; Escape равен Отмене. Отмена удаляет только черновик. Успешная запись и отмена имеют разные назначения:

| Источник и режим | Начальный ввод / действие | Успешная запись | Отмена / Escape |
|---|---|---|---|
| S-01 → новая поездка | Пустое название / Создать | Новая Trip → её S-02, фильтр «Все» | S-01 без новой поездки |
| S-02 → добавить вещь | Пустое название / Добавить | Та же Trip.id в S-02, текущий фильтр | Та же S-02 без новой вещи |
| Строка вещи S-02 → правка | Текущее название / Сохранить | Та же Trip.id и Item.id, новый текст, packed не меняется | Та же S-02, прежнее имя |

Возврат из добавления/правки сохраняет выбранную поездку и текущий фильтр. Это интерфейсное уточнение контекста возврата, не новое доменное правило. На карте стрелка `saveedge` обозначает результат **успешной** записи во всех трёх режимах; при ошибке перехода нет. Две стрелки от `cancel` показывают возврат к источнику. Родитель формы создания — S-01, хотя успешный результат открывает новую S-02.

## Сценарии и состояния

- **UC-01 создать/выбрать.** Пустой S-01 → «Новая поездка» → S-03 → Создать → новая S-02. Для существующей поездки: её строка S-01 → S-02 с соответствующей Trip.id. Назад возвращает в список; вещи разных поездок независимы.
- **UC-02 добавить.** S-02 → Добавить вещь → S-03 → Добавить → та же S-02. Новая вещь не собрана, добавляется в порядке добавления; дубликаты разрешены. Отмена не создаёт вещь.
- **UC-03 переименовать.** Строка вещи → Править → исходное имя в S-03. Отмена сохраняет исходное имя; повторное открытие и успешное Сохранить меняют только имя, сохраняя ID и packed.
- **UC-04 отметить/вернуть.** Отметка конкретной вещи записывает packed. В «Осталось» успешно отмеченная вещь исчезает из списка; для возврата пользователь переключает «Все» и снимает отметку с этой вещи. Неопределённый feedback/Undo из прежнего описания убран: отдельное действие моделью не задано.
- **UC-05 показать остаток.** «Осталось» показывает только несобранные вещи выбранной поездки. Поездка без вещей показывает пустой список и добавление; поездка с вещами, у которой остаток равен нулю, — «Всё собрано». Эти состояния не смешиваются.
- **UC-06 продолжить позже.** Обычное открытие поездки из S-01 начинает с «Все». Browser reload восстанавливает last-trip и фильтр по candidate assumptions модели, а также подтверждённые вещи и packed. Восстановление незаписанного черновика не обещано.

Сквозная сверка: создать первую поездку → добавить вещь → отметить → «Осталось» → «Все» → вернуть → Назад → создать вторую → выбрать первую → reload. Владельцы операций и возвраты сохраняют контекст поездки; переходы и действия доступны через S-01–S-03 без новой поверхности.

**DR-02: ввод и отмена.** Перед записью применяется trim; пустое/пробельное имя даёт inline error и фокус на поле. Ограничение длины не вводится. Длинное название должно переноситься, не вытесняя действия. Отмена/Escape ничего не записывают.

**DR-03: ошибки и подтверждение.** Подтверждение и переход происходят после записи. Ошибка создания/добавления/правки оставляет S-03 с введённым черновиком и прежними данными; та же кнопка позволяет повторить, не создавая дополнительный объект от неудачной попытки. Ошибка отметки оставляет прежний packed и показывает сообщение в S-02. Ошибка чтения показывается как блокирующее сообщение в месте входа/восстановления без перезаписи повреждённых данных; автоматическое восстановление, сброс и новые команды восстановления не придуманы.

Сохранность по модели ограничена localStorage одного browser origin: это не backup, перенос или native lifecycle. При недоступном storage нельзя показывать ложное «сохранено». Исполнение этого контракта здесь не тестировалось.

## Что исправлено и как проверить

В карте сохранены все исходные 16 node IDs и 5 edge IDs, в том числе S-01–S-03; новые группы и строки дополняют исходные. Теперь видна композиция S-01 → список → поездка → информация/открытие и S-02 → список → вещь → информация/отметка/правка. Добавлены название/общий прогресс S-02, содержание формы, состояния, легенда и возвраты. Цвета: серый — информация, голубой — локальный ввод/фильтр, синий — навигация, зелёный — запрос изменения данных. Стрелки начинаются у команд; вложенность не заменена стрелками.

Описание согласовано с моделью: устранён общий «возврат к родителю» после создания поездки, разведены обычное открытие и reload, убрана ссылка на отсутствующий blocks.html. Приоритет остаётся у остатка и добавления, затем правки. Native/accessibility review и device checks остаются за пределами этой сверки; их результаты не заявлены.

Проверки beta.15: JSON/уникальность IDs/ссылки стрелок — OK; физическое владение для S-01, S-02, S-03 — PASS. SVG fallback создан для проверки: после исправлений нет предупреждений о пересечении содержимого, подписей, заголовков групп и переполнении текста. Это автоматическая геометрическая проверка, не визуальный просмотр: Pillow и доступный браузер отсутствуют, Obsidian не открывался. Временный SVG удалён; постоянный результат — только эти два артефакта. Реальный vault root неизвестен; file nodes отсутствуют, поэтому проверка JSON не зависит от разрешения ссылок vault. Registry не создавался в соответствии с ограничением на два артефакта.
