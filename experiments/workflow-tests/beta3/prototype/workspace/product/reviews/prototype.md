# Функциональный прототип — технический эксперимент

Дата: 2026-10-10. Входы: [accepted.md](../../accepted.md), [структура](structure.md), [Canvas](structure.canvas). Реализация: [index.html](../../prototype/index.html), [app.js](../../prototype/app.js). Использован Fab prototype; это техническая проверка плагина, не принятие интерфейса создателем.

## Запуск

Из корня workspace:

```sh
python3 -m http.server 8765 --bind 127.0.0.1
```

Открой http://127.0.0.1:8765/prototype/ в современном браузере. Остановить сервер: Ctrl+C. На момент подготовки сервер запущен инструментом в сессии 33795; для повторного запуска сначала останови его, если порт занят. Зависимостей и установки пакетов нет. Проверка кода: `node --check prototype/app.js`; тест логики: `node prototype/check.cjs`.

## Scope и принятые для эксперимента уточнения

UC-01–UC-06, DR-01–DR-05, S-01–S-04 сохранены. S-01 — список с быстрым поливом, S-02 — выбранная карточка со встроенной историей, S-03/S-04 — модальные формы. Отдельный блоковый макет пропущен по явному разрешению пользователя; полный дизайн-пайплайн не проверялся.

По текущему запросу исправление удаляет выбранную ошибочную запись; напоминание — необязательный свободный текст, без доставки уведомлений. Полив получает текущее время. Допущение формы: название обязательно после trim, одинаковые имена разрешены, произвольный лимит длины не введён. Эти решения не означают принятия будущего продукта.

Сохранение синхронное: сначала localStorage.setItem, затем обновление состояния и закрытие формы. Ошибка оставляет форму, название и напоминание; полив/удаление при ошибке не меняют историю. Компактная тестовая кнопка переключает одноразовую ошибку следующего сохранения, до записи в storage; валидация не расходует ошибку. Повторный клик по кнопке снимает ошибку. Отмена, Escape и клик за пределами sheet закрывают черновик без сохранения. Синхронная блокировка действует только на время операции; отдельные последующие клики полива считаются отдельными фактами, временное подавление повторов не введено.

## Что фактически проверено

`node --check` прошёл. `node prototype/check.cjs` прошёл на Node 22.16.0: создание и отмена, пробельное название, ошибка создания и повтор, необязательное напоминание, привязка полива к растению, модель отображения истории, ошибка удаления и повтор, редактирование и отмена, ошибка редактирования и повтор, восстановление сохранённых данных новым экземпляром приложения, ошибка полива. Harness выполняет настоящий app.js с подставными DOM и storage; он не доказывает браузерный рендер, события клавиатуры или реальную долговечность localStorage.

HTTP-сервер действительно запущен на 127.0.0.1:8765 после разрешённой sandbox escalation. Проверка UI не состоялась: CUA вернул `Browser is not available: iab`, затем `Computer Use was not approved to use Google Chrome`. Отказ инструмента не обходился. Наблюдений успешной работы в настоящем браузере нет.

## Ручная проверка в браузере — пока не выполнена

1. В пустом списке открой создание; введи название и напоминание, отмени. Список остаётся пустым.
2. Создай растение через Enter в поле названия. Создай второе кнопкой, без напоминания. Полей не должно остаться на экране после успеха.
3. В списке отметь полив первого растения. Открой обе карточки: полив должен быть только у первого. Удали ошибочную запись в его истории; останься в той же карточке.
4. Измени оба поля и отмени; проверь старые значения. Повтори и сохрани; проверь новые значения.
5. Введи черновик создания/изменения, включи ошибку следующего сохранения и отправь форму. Проверь видимую ошибку, открытый sheet и оба введённых значения; повтори сохранение, проверь успех.
6. Включи ошибку перед поливом и перед удалением: сохранённая история не должна измениться; повтор должен сработать.
7. Перезагрузи страницу после сохранения: растения, напоминания и поливы должны сохраниться. Черновики и переключатель ошибки не сохраняются.
8. Проверь Escape, клик за пределами sheet, возврат к прежнему положению списка; на ширине 320px — длинное название без пробелов и многострочное напоминание. Эти проверки, реальное Enter-submission и визуальная доступность пока не подтверждены.

## Технические границы

Настоящий код использует localStorage с ключом `fab-plant-care-prototype-v1`: данные привязаны к origin и профилю браузера. Очистка сайта удалит данные; смена порта/хоста даёт другое хранилище. Нет резервной копии, переноса устройств или согласования нескольких вкладок. Проверка восстановления выполнена только с storage-моделью; реальное reload persistence остаётся пунктом браузерного прогона. Повреждённые данные/ошибка чтения блокируют перезапись и сообщаются, их восстановление UI не реализовано. Ошибка квоты/доступа обрабатывается тем же catch, но реально не воспроизводилась.

Нет аккаунтов, оплаты, cloud sync, native app, уведомлений и финального оформления. Это работоспособный кандидат для локального просмотра, не доказательство production readiness или creator/usability acceptance. Следующий шаг — описанный браузерный прогон при доступном UI; расширение scope не требуется.
