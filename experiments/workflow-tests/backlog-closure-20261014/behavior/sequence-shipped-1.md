Three useful directions:

- **Clearer wording:** explicit labels, “Phone (optional),” and a submit button such as “Register for the event.” A small change if the main issue is ambiguity.
- **Better completion and recovery:** explain errors beside the affected fields, preserve entered values after a failed submission, and show a clear confirmation after success. This is my preferred starting point because it addresses whether someone can finish reliably.
- **More context:** explain what registration secures and what happens afterward. Useful if people hesitate because the event or confirmation process is unclear.

These can coexist, but the priority should follow the problem you want to solve. Which is closest: people hesitate before submitting, get stuck completing the form, or submit successfully but remain unsure they’re registered?
