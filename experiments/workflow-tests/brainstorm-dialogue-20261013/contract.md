# Brainstorm dialogue experiment

Date: 2026-10-13. Owner: main Fab chat. Branch: codex/fab-brainstorm-dialogue.
Source baseline: beta.23 package at source checkpoint 43ba2f5. Candidate changes
Brainstorm only; shared core and other skills remain byte-identical. No install,
merge or release. Real-use monitoring and private project data are outside this test.

Hypothesis: operational dialogue moves improve material contribution, grounded
critique and useful questions without forced hats, premature closure or intake burden.
Existing shared-core obligations may already produce strong baseline responses.

Method: four matched synthetic cases under direct skill entry; three have actual
scripted follow-ups in resumed conversations, one is a brevity/accepted-scope control.
Baseline/candidate start in separate fresh CLI contexts with the same user settings.
No extra observer agent. Root qualitative review is unblinded, not independent.
Inputs are frozen before runs and do not contain scoring expectations.

Judge: a materially different insight/mechanism, reasoned causal critique, questions
that change the choice when needed, uptake of follow-up, accepted constraints,
proportionality and absence of forced roles/sections. No requirement to ask questions
or object in every turn. The follow-up scripts are simulated creator input; they do
not establish real human usefulness or acceptance. Do not score keyword counts.

Budget: initial comparison 14 model turns; up to two targeted corrective turns only
for a substantive failure with a new candidate. Maximum 16 turns, 35 minutes wall
for model work. Estimated input up to 1.5M tokens and output 20K before pilot; not
a hard per-turn cap. Observe actual usage and adjust after pilot. Stop at useful
bounded evidence, a defeated comparison, repetition or window exhaustion. No reset.

Use the CLI default configured model/effort; verify actual metadata from each
rollout and record unknown if unavailable. Capture raw events, turn usage, wall,
responses and interventions; failures retain their own evidence. Run read-only
against task-owned package snapshots; no product edits or remote actions. Keep
raw evidence ignored, promote useful responses/results, verify retention and remove
only owned temporary workspaces at completion. No global-mode maturity claim.

## Pilot amendment before additional entry probes

The paired exploration pilot did not reproduce a passive baseline: both responses
already added causal alternatives and a useful question. To distinguish direct
skill conditioning from an ordinary capability route, use the two reserved turns
for a matched Cowork entry asking for five ideas, without naming Brainstorm in the
request. The 16-turn ceiling is unchanged; no corrective turns remain unless a
new budget is explicitly agreed. This is a source-snapshot route check, not native
installed discovery. Additional input is frozen before those runs.
