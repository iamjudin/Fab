# Интерфейс — кандидат v1

Основания: SLICE-01, UC-01…08, DR-01…07. Все поверхности candidate, без клиентского acceptance. Структура → критические сценарии → блочные экраны выполнены до prototype, это не early shortcut.

## Структура и доступ
| Surface | Назначение / состав | Действие и владелец | Переход / возврат |
|---|---|---|---|
| S-01 | Главный экран координатора: событие, готовность, фильтры, коллекция задач | Создать — экран; открыть — конкретная карточка | Создать → S-03; карточка → S-02; закрытие возвращает фильтр и прокрутку |
| S-04 | Главный экран волонтёра: мои текущие, готовые, отменённые | Открыть — своя карточка | S-02; назад сохраняет выбранный фильтр |
| S-02 | Модальные детали: название, инструкция, назначение, статус, действия, история | Каждое действие принадлежит открытому поручению | Изменить → S-03; отменить → S-05; закрыть → исходный список |
| S-03 | Модальная форма создания/редактирования, все начальные поля | Сохранить — форма; выбрать исполнителя — локальный draft | Успех create → S-01; edit → S-02. Отмена/Escape → источник, без записи |
| S-05 | Подтверждение отмены с названием и последствием | Подтвердить — конкретная задача | Подтверждение или отказ → S-02; история и данные сохраняются |

Первичный вход — обзор координатора; демонстрационная панель отдельно переключает роль/волонтёра, не выдавая себя за login. При смене роли открытые детали закрываются, фильтр новой роли сбрасывается на текущую работу. Главный экран волонтёра не показывает общий dashboard; так контекст ответственности не размывается. Предполагается частое обращение к спискам, это гипотеза.

Выбор деталей вместо inline-edit: инструкция, статус и история остаются в одном контексте, меньше случайных действий в списке. Форма не требует create-then-configure: инструкция и назначение доступны сразу. Готовность меняется в деталях одним действием, Undo доступен позже, без таймера. Форма отмены требует явного подтверждения, но восстановление не скрыто в техническом меню.

## Критические сценарии
1. UC-01: S-01 → Создать → S-03. Пустые данные: inline ошибка, draft сохраняется. Enter и кнопка проходят одну submit-ветку. Отмена/Escape: S-01, без объекта. Успех: новая карточка + сообщение о локальной записи.
2. UC-02: карточка → S-02 → Изменить → S-03. Назначение — draft до Save. Cancel возвращает S-02 с прежним человеком. Save обновляет детали/историю/личный список; ready не сбрасывается.
3. UC-03/04/05: S-04 текущие → S-02 инструкция → Готово → статус и история. S-04 готовые позволяет вернуться позже → Вернуть в работу → снова текущие. Реальная identity отсутствует.
4. UC-06: S-01 → S-02 → исправление отметки → обновлённая готовность и история с автором. Цель — заявленный факт; quality approval не подразумевается.
5. UC-07/08: S-02 → S-05 → отказ без изменения / подтверждение сохраняет данные, исключает из active. S-01 отменённые → S-02 показывает сохранённую готовность → восстановить → прежний статус в active. Нет удаления.
6. Ошибка записи: синхронная подтверждённая неудача localStorage или demo toggle; прежние данные не изменены. Форма и draft остаются, повтор безопасен после отключения toggle. Не симулируем неизвестный сетевой исход. Повреждённые данные: блокировка изменений, явный demo reset с подтверждением.

## Блочные экраны
Визуальный кандидат: [blocks.html](blocks.html). Он создан перед runtime. Верх — контекст события/роли; ниже результат и фильтры; далее карточки с названием, исполнителем и статусом. На 390px список одноколоночный. Детали приоритетно показывают инструкцию и статус, затем действие, затем историю. Создание и редактирование используют один состав полей. Пустой личный список даёт ясный результат без fake tasks. Контрольные состояния: непустой список, пустой список, готовая задача, отменённая с сохранённой готовностью, ошибка формы и ошибка записи.

Критерии: текстовый статус помимо цвета, цели касания ≥44px, label на input, клавиатурная форма/Escape, длинные слова переносятся, смысл и данные не обрезаются. Это критерии кандидата, не доказанная usability или native mobile fidelity.
