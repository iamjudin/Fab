# Обзор структуры: уход за растениями

Версия: 2026-10-10. Основания: [accepted.md](../../accepted.md), [.wireframer](../../.wireframer/graph.json), текущий запрос. Продукт личный. Требования приняты; организация интерфейса и уточнения ниже — кандидат, не новое пользовательское принятие.

[Открыть Canvas](structure.canvas). Корень для относительных Canvas-ссылок: `/private/tmp/fab-beta2-domain-20261010` (локальный корень просмотра; реальный Obsidian vault не предоставлен). Переносить весь workspace либо пересчитать пути относительно своего vault.

## Use Cases текущего среза

| ID | Принятое поведение | Вход / результат |
|---|---|---|
| UC-01 | Просмотреть растения и открыть выбранную карточку | S-01 → S-02 выбранного растения |
| UC-02 | Добавить растение с названием и необязательным напоминанием | S-01 → S-03 → растение в списке |
| UC-03 | Отметить полив выбранного растения из списка | Действие внутри элемента S-01 → запись в истории этого растения |
| UC-04 | Просмотреть данные и историю поливов растения | S-02, история встроена |
| UC-05 | Изменить название и напоминание растения | S-02 → S-04 → обновлённая карточка |
| UC-06 | Исправить ошибочно отмеченный полив через историю | Запись в истории S-02 → исправленная история |

Новые цели не добавлены. Удаление растения, ручное добавление старых поливов и перенос даты полива не входят в этот обзор.

## Правила, необходимые для структуры

- DR-01 — принято, существующий ID сохранён: отмена не меняет сохранённые данные; ошибка сохраняет ввод. Для создания и редактирования неуспешное сохранение оставляет форму открытой с введёнными значениями. Успех означает подтверждённое сохранение, а не нажатие кнопки.
- DR-02 — принятое следствие требований: полив и история принадлежат конкретному растению. Действие в строке списка и действие в записи истории не являются глобальными.
- DR-03 — принято: название и необязательное напоминание доступны при создании и редактировании; OS уведомления не подтверждены. Напоминание — настройка растения, не настройка приложения и не разрешение ОС.
- DR-04 — кандидат: исправление ошибочного полива удаляет выбранную запись из истории. Это самый узкий способ убрать ошибочно отмеченный факт; редактирование даты потребовало бы дополнительных правил и формы. После успеха история обновляется в той же карточке; при ошибке запись остаётся.
- DR-05 — кандидат: быстрый полив добавляет запись с текущим временем после успешного сохранения. История отражает сохранённые факты. Защиту от повторного нажатия и неопределённого результата сохранения нужно определить перед реализацией; карта не доказывает её наличие.

## Поверхности и доступ

| ID / статус | Назначение и представление | Контроль-владелец / куда ведёт / возврат |
|---|---|---|
| S-01 / candidate | Главный экран: список растений с действиями у каждого растения | «Добавить» принадлежит экрану → S-03; «Открыть карточку» принадлежит растению → S-02; «Отметить полив» сохраняет факт на месте |
| S-02 / candidate | Карточка растения: данные и встроенная история | «Изменить» принадлежит карточке → S-04; удаление принадлежит выбранной записи истории, остаёмся в S-02; «Назад» → S-01 |
| S-03 / candidate | Создание растения: modal sheet из списка | Название и напоминание — локальный ввод; «Создать» сохраняет → закрытие в S-01 при успехе; «Отмена» → S-01 без изменений |
| S-04 / candidate | Редактирование растения: modal sheet из карточки | Те же поля с сохранёнными значениями; «Сохранить» → закрытие в S-02 при успехе; «Отмена» → S-02 без изменений |

S-01 → S-02 образуют navigation stack. Modal sheets возвращают к открывшему контексту. Возврат из карточки сохраняет положение списка; редактирование возвращает к тому же растению. При создании пустой список всё равно предоставляет «Добавить». Жест закрытия формы трактуется как отмена; необходимость предупреждения о несохранённом вводе пока не определена.

## Почему так

Список — главный контекст по accepted.md. Быстрый полив остаётся у растения, потому что это прямо принято. Предположение о частом использовании полива не подтверждено наблюдениями, но для выбора главного экрана такие наблюдения сейчас не нужны.

История остаётся встроенной в карточку: она объясняет состояние конкретного растения и даёт доступ к исправлению. Отдельный экран истории добавил бы переход без независимой задачи в этом срезе. Если реальная история окажется длинной, её представление потребует пересмотра; это не основание заранее заводить вкладку.

Рекомендуемый кандидат — две короткие modal sheets с одинаковыми полями. Альтернатива — полноэкранная форма в navigation stack: полезнее при расширении данных и сложных настройках. Сейчас размер задачи и возврат к контексту говорят за sheet. Встроенное редактирование в карточке сэкономило бы переход, но смешало бы чтение и черновик; отдельная форма яснее выражает сохранение и отмену.

На карте вложенные рамки показывают состав: экран → коллекция → один пример элемента → сведения и действия. Стрелки начинаются у конкретного навигационного действия. Зелёное действие означает запрос на сохранение, не доказательство успеха; автоматическое закрытие после успеха описано здесь и в заголовке карты, а не представлено как отдельная кнопка навигации.

## Важные неизвестности

1. Формат напоминания: интервал, дата/время или иной параметр не принят. На карте это одно поле без выдуманного расписания. Реальные OS уведомления, разрешения и доставка не реализованы/не подтверждены; обещать доставку нельзя.
2. Исправление полива: удаление ошибочной записи — кандидат. Если требуется менять дату или отменять удаление, изменятся правила и, возможно, точки доступа. Подтверждение удаления или Undo здесь не заявлены готовыми решениями.
3. Семантика названия: обязательность, ограничения и совпадающие имена неизвестны. Это правила формы для следующей детализации, не препятствие обзору.
4. Локальное сохранение, повторы и неопределённый результат: механизм не проверен. Требование сохранять ввод принято, техническая гарантия не получена.
5. Сортировка, визуальные признаки напоминания и большой объём истории не определены. Они влияют на будущий макет, не требуют новых разделов сейчас.

Ни одна из этих неизвестностей не блокирует кандидат обзорной структуры. Подробные сценарные карты, блоковые макеты и прототип не создавались.

## Проверка

Семантически пройдены вход, владелец действия, изменение контекста и возврат для UC-01–UC-06. Проверены пустой список, одинаковая конфигурация при создании/редактировании, отсутствие изменений при отмене и сохранение контекста при исправлении истории. Это авторская проверка модели, не пользовательский тест.

JSON/ссылки и граф проверяются штатным валидатором Fab; SVG — приближённое превью для визуальной проверки. Открытие и рендер в Obsidian не проверены, фактический vault не указан.

Фактический результат проверки: граф и Canvas-ссылки — OK. SVG сгенерирован, автоматический геометрический preflight не выдал предупреждений. Полная визуальная проверка превью недоступна: Pillow отсутствует, CUA не предоставил браузеров. Поэтому читаемость в реальном рендере остаётся непроверенной; SVG предоставлен для просмотра. Цвет навигационных контролов осветлён для контраста с тёмным текстом.
